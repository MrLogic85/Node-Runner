Two shapes -- a **dialog** (over a dimmed screen) and a **notification** (at the bottom edge, tap to act, never blocking controls) -- each in three severities, `default`, `warn` and `danger`, the same idea as chips and frames elsewhere. Severity colours the border and the glow; a warning or danger popup also names itself above its title ("Warning", "Danger") in that colour, and a default one has no such label. The icon next to it is picked by whoever raises it; when none is picked, a default popup shows the Brain mark and a warning or danger popup the warn icon.

**The dialog** is icon + label + title, then body text, then its two buttons in the card action bar (`c_card_actions`) along the bottom edge, flush with the frame: ordinary stacked buttons with text only, sharing the width, a hairline above and between. Cancel is always `secondary`. Continue's own kind follows the severity -- `primary` (accent text) for `default`, `flat` (plain text, no colour claims the tap) for `warn`, `tertiary` (danger text) for `danger`. Every button acts on a **tap**. The dialog can also carry one optional **error line**, always danger-coloured regardless of its own severity, for a problem with its own content or an action that failed ("Could not delete Walker. Try again."); while the action runs its buttons are disabled. A tap outside never dismisses it; Back cancels.

The real dialogs today:

- **Unlock dialog** (`default`). Tapping the padlock in Build. Unlocking keeps the training and lasts until Build is left.
- **Reset training dialog** (`danger`). In Build's overflow once trained. Names the generations it forgets, keeps the body, suggests Copy first.
- **Delete dialog** (`danger`). Delete on a card in Creations or in Build's overflow. Says the creation is removed for good and suggests Copy first. Reset training and Delete creation may sit next to each other in a menu, because each asks first.
- **Restore checkpoint dialog** (planned, with Checkpoints). Restore in a checkpoint card's own action row, on Checkpoints. Names the checkpoint, warns that it overwrites the player's current progress (structure and training both), and suggests making a new checkpoint of the current state first.
- **Delete checkpoint dialog** (planned, with Checkpoints). Names the checkpoint, says it is removed for good. Deleting one checkpoint never touches active or any other checkpoint.

There is no Copy dialog: Copy makes an identical creation at once and opens it. There is no Save-checkpoint dialog either: it saves at once, already named by generation.

**The notification** is the same icon + label + title, then one line of body text, no buttons. It swipes away, lives 5 s, shows one at a time and waits while a dialog is open. Used today for "coming in a later version" answers (a tap on Stats or the trophy), "Creation copied" after Copy creation, "Code copied" after Share build, "Locked: the brain is trained for these parts." on a locked part in Build, and load or save errors (`danger`). The **achievement toast** (planned) uses the same shape.
